Заголовок: Cloudflare CDN: эталон (для зарубежа и резерва)

Это разбор одного провайдера. Общая база (XHTTP-инбаунд + nginx на ноде-ориджине) и режимы «через GET / через POST» описаны в обзорной статье «CDN-фронтинг: спрятать ноду за CDN».

Если есть домен на Cloudflare, это самый предсказуемый фронт по поведению (динамика не кешируется, методы/заголовки проходят из коробки). Но для РФ-аудитории у него свои минусы, поэтому он остаётся эталоном для зарубежа и резерва, а не основным РФ-каналом.

📖 Незнакомые слова? Все термины простыми словами смотрите в Словаре терминов.

✅ Плюсы: не кеширует POST/long-GET по умолчанию (динамика), XHTTP (транспорт за CDN) проходит даже там, где WS/gRPC нет, бесплатный план, мировой охват. ❌ Минусы: из РФ DNS Cloudflare медленный, оплата из РФ недоступна; для российской аудитории как основной фронт ненадёжен.

Настройка по шагам
Домен на NS Cloudflare; запись cdn (A → IP ноды) в режиме Proxied (оранжевое облако).
SSL/TLS → Full. Кеш не трогает POST/long-GET по умолчанию (динамика не кешируется).
XHTTP проходит даже там, где WS/gRPC нет; самым совместимым считается режим packet-up.
Клиент (Host в Remnawave): cdn.your.domain:443, path=/xh, режим packet-up.

⚠️ Из РФ DNS Cloudflare медленный, а оплата из РФ недоступна. Но как фронт для зарубежной аудитории/резерва Cloudflare остаётся эталоном. Для РФ-аудитории комбинируйте: прямой Self-steal Reality (маскировка под свой сайт-заглушку; основной) + XHTTP за CDN (резерв), а из РФ-CDN берите Yandex CDN.

Связано: обзорная «CDN-фронтинг» (база), «Yandex CDN (рекомендую)» (РФ-фронт), «Профили подключений» (Self-steal Reality как основной канал).
