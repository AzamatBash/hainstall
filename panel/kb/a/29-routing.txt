Заголовок: Маршрутизация: RU-сайты напрямую, остальное через VPN

С 2025–2026 российские сервисы по требованию РКН режут доступ через VPN: Ozon, Wildberries, Кинопоиск, Иви, Yandex Pay, банки, госуслуги, операторы. Если весь трафик клиента идёт через зарубежную ноду, он теряет к ним доступ и уходит. Решение: сплит-роутинг (правила «какой трафик куда»):

text
РФ-сайты/сервисы ──▶ direct (выходят с домашнего IP клиента, быстро и не блокируются)
Всё остальное ──▶ proxy (через вашу VPN-ноду — то, что заблокировано в РФ)

Плюс бонусом: РФ-сайты грузятся быстро (без крюка через заграницу), а нагрузка на ваши ноды падает.

Зачем роутинг через ядро Xray: большие плюсы

Сплит-роутинг живёт в ядре Xray на клиенте, и это даёт то, чего не получить «тупым» VPN «всё через ноду»:

Итог: пользователь получает «невидимый» VPN: заблокированное открывается, а российские сервисы, банки и IP-проверки ведут себя так, будто VPN выключен. Готовый geo-dat-free шаблон с балансером смотрите в «СУПЕР-АВТОВЫБОР» и «Балансировщики».

Как раздать клиентам через Remnawave

Routing-правила доставляются клиенту в подписке, через шаблон ядра:

Subscription templates (в панели/подписочном сервисе): для ядра xray-json (и/или sing-box, mihomo) вставьте блок routing выше в шаблон. Плейсхолдер прокси ($payload$ / список хостов) Remnawave подставит сам.
Клиенты на этих ядрах (Hiddify, v2rayNG, Streisand, sing-box) получат роутинг автоматически при импорте подписки: пользователю ничего не настраивать.
Для разных тарифов можно держать разные шаблоны (напр., «всё через proxy» vs «RU-direct») и отдавать их через External Squads / Routing Rules.

Тонкость: geosite/geoip базы (geosite.dat, geoip.dat) должны быть на клиенте свежими: Hiddify/v2rayNG обновляют их сами; для своих сборок обновляйте периодически (списки РФ-доменов меняются).

Happ-routing (в приложении Happ)

Happ это популярный клиент с гибким роутингом. Два способа:

Где создавать свои правила: соберите свой набор маршрутизации визуально (что в direct, что в proxy, что в block) и выгрузите готовый файл/ссылку в конструкторе Happ-routing → https://utils.docs.rw/happ-rb. Удобно сделать свой пресет «РФ → direct, остальное → proxy» один раз и раздавать клиентам одной ссылкой.

Конструктор utils.docs.rw/happ-rb: визуально задаёте DIRECT (РФ напрямую), PROXY (всё остальное через VPN) и BLOCK, а справа получаете готовую ссылку + QR и JSON для импорта.

А. Авто из подписки (проще). Happ умеет принимать Happ-routing прямо из подписки Remnawave: в подписочном шаблоне для Happ задаёте те же правила (RU → direct, остальное → proxy): при импорте ссылки правила применяются сами. Пользователю достаточно вставить вашу подписку.

В панели (настройки подписки) → поле Happ routing: вставляете сюда ссылку из конструктора и жмёте «Настроить Happ Routing». Соседнее поле Announce: текст, который клиент видит под названием подписки.

Б. Вручную в приложении. В Happ: Настройки → Маршрутизация (Routing) → добавляете наборы правил:

text
Direct → geosite:category-ru, geoip:ru, gosuslugi.ru, sberbank.ru, ozon.ru, wildberries.ru …
Block → geosite:category-ads-all (по желанию)
Proxy → по умолчанию (всё остальное)

Happ поддерживает rule-sets (geosite/geoip) и импорт набора правил по ссылке: можно выложить готовый JSON роутинга и дать клиентам одну ссылку.
Порядок правил тот же: сначала direct для РФ (домены+IP), в конце proxy для всего остального.
Включите опцию «обход для России / Russia bypass», если она есть в вашей версии, это тот же geosite:category-ru → direct.

Точные подписи пунктов меню Happ зависят от версии; принцип неизменен: РФ → Direct, остальное → Proxy, правила сверху вниз.

Продвинутый роутинг (geo-dat-free + анти-фрод)

Сплит-роутинг выше это рабочая база. Но в боевом сервисе вскрылись три вещи, которые ломают наивную схему. Полный разбор + готовый шаблон балансера смотрите в статье «СУПЕР-АВТОВЫБОР»; здесь только суть.

1. Анти-фрод РФ-сервисов сидит на ЗАРУБЕЖНЫХ доменах. Магнит, Т-Банк, Дикси, почти все мобильные аппы проверяют «VPN ли это» через домены вида terratraf.io, t-tech.team, gravityfield.ai, diginetica.net, appsflyer.com, onelink.me, branch.io, adjust.com. Если гнать их через RU-ноду, по geoip назначения они уйдут за границу → анти-фрод увидит датацентровый IP → «VPN detected». Лечится только direct (домашний резидентный IP юзера). Поэтому в direct кладите не только.ru, но и эти зарубежные домены РФ-сервисов.

2. geosite:/geoip: могут уронить клиента. Правила выполняются на КЛИЕНТЕ его файлом geosite.dat. У части юзеров он урезан → краш ядра geosite.dat отсутствует секция YOUTUBE (volumes с geo-файлами на нодах не помогают: правила-то на клиенте). Надёжнее geo-dat-free: вместо geosite:category-ru → `regexp:\.ru$|\.su$|\.xn--p1ai$` + явные не-.ru домены; вместо geosite:youtube → явные googlevideo.com/ytimg.com/…; вместо geoip:private → CIDR.

3. Порядок важнее списка: TikTok идёт выше RU-правил (иначе уйдёт в direct и не откроется в РФ); YouTube → RU-нода (без рекламы, см. «Каскад»); сайты-проверки IP (2ip.ru) → RU-нода (чтобы юзер видел РФ-IP); QUIC udp:443 → block (иначе видео залипает в туннеле).

Полный geo-dat-free шаблон с балансером leastLoad, анти-фрод-списком и «одной плиткой на тариф» смотрите в «СУПЕР-АВТОВЫБОР».

Чего сплит-роутинг не даёт
Не прячет вас от российских сайтов. Они видят ваш домашний адрес — в этом весь смысл, но и анонимности там никакой.
Списки устаревают. Сервисы переезжают на новые домены и адреса, правила приходится обновлять.
Не работает без нормального клиента. Приложения, которые не читают JSON-подписку, правила просто проигнорируют.
Усложняет жалобы. «У меня не работает сайт» теперь может означать и проблему маршрута, и проблему ноды — проверять придётся оба варианта.
Проверка
Откройте РФ-сайт (банк/госуслуги), должен открыться с российским IP (проверьте на 2ip.ru: адрес должен быть ваш домашний, не ноды).
Откройте заблокированный в РФ ресурс, должен открыться через ноду (IP должен быть вашей ноды).
Если РФ-сайт идёт через прокси (медленно/«VPN detected»), добавьте его домен в список direct.

Связано: «Заблокировали IP?» (антиблок и «белые списки»); «Профили подключений» (WARP, сервис Cloudflare как «чистый» выход наружу, для отдельных сервисов вроде ChatGPT); отдельный гайд про клиентские приложения.

Проверено на Xray-core 26.x и Remnawave 3.4.x — сентябрь 2026.
