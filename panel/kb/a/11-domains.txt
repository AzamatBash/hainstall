Заголовок: Домены: где брать и подключить к Cloudflare

Домен это лицо вашей инфраструктуры. Неправильный домен выдаёт назначение, приглашает сканеры/брутфорс и попадает в блок-листы. Несколько жёстких правил.

📖 Незнакомые слова? Все термины простыми словами есть в Словаре терминов.

Правила выбора домена

1. Никаких «говорящих» слов. В домене и сабдоменах нельзя vpn, впн, proxy, прокси, free, unblock, tor, xray, marzban, remnawave. Такие домены эвристики и блок-листы ловят пачками. Берите нейтральное: бренд, абстракция, обычное слово (cloudmesh.io, brightpath.net).

2. Не RU-зона для нод и панели..ru /.рф /.su под ноды и панель это категорически нет: - регистрация РФ-доменов с 1 сентября 2025 идёт только через Госуслуги (деанон владельца); - РКН имеет прямой рычаг: может разделегировать/изъять, а РФ-регистратор обязан исполнять предписания.

Берите нейтральные зоны (.com /.net /.org /.xyz /.shop /.online) у зарубежного регистратора. РФ-домен допустим разве что под сервер подписки (он отдаёт только страницу/конфиг, не трафик), но и тут зарубежный лучше.

3. Панель НЕ на сабдомене panel. panel.домен, admin.домен, marzban.домен это приглашение: недоброжелатели сразу находят вход и начинают подбор пароля. Панель вешайте на невзрачный/случайный сабдомен (a7f3.домен, cp.домен, mgmt.домен) и не светите его (нет в подписке, нет в боте), плюс закройте basic-auth / IP-allowlist (см. «Чтобы не угнали»).

4. Сабдомены нейтральные. Ноды: node1, s1, de1, cdn, static, img. Подписка: sub, s. Цель: выглядеть как обычная инфраструктура сайта.

Почему нельзя DuckDNS (и другой бесплатный dynamic-DNS)

DuckDNS даёт не свой домен, а поддомен что-то.duckdns.org. Это плохо по всем фронтам:

Грязный «родитель». На duckdns.org сидят тысячи абузеров, домен давно репутационно гнилой и в блок-листах. Режут его пачкой (collateral block): заблокируют чужой поддомен, заодно ляжет ваш.
Нет своей зоны на Cloudflare. У вас нет apex-домена → нельзя добавить зону в Cloudflare, нет управления DNS-записями, нет проксирования/CDN, нет нормальных сертификатов под свой домен.
Не годится для Reality / self-steal. (Reality: маскировка VPN под настоящий чужой сайт; self-steal: под ваш собственный сайт-заглушку.) Маскировка требует правдоподобного своего домена с TLS 1.3 (обычное шифрование HTTPS, тот самый «замочек» в браузере). *.duckdns.org для serverNames это палево, не выглядит как настоящий сайт.
Зависимость от чужого крючка. DuckDNS может отозвать/удалить поддомен, ввести лимиты, упасть, и ваш сервис повиснет на чужом бесплатном сервисе.
Целиком под риском. duckdns.org может попасть под блокировку РКН целиком, и вы ничего не сделаете.

Свой домен за ~1–2 $/год снимает все эти проблемы. Бесплатный dynamic-DNS это ложная экономия.

⛔ Про Cloudflare и доступ из России

Одна настройка Cloudflare способна закрыть ваш домен для всей российской аудитории, и выглядит это как «сайт открывается только с VPN».

Речь про ECH (Encrypted Client Hello) — режим, в котором браузер шифрует имя сайта в самом начале соединения. Фильтрующее оборудование у оператора имя не видит и на всякий случай рвёт соединение целиком. Работает не у всех одинаково: тот, чей браузер не получил специальную DNS-запись, подключится нормально, а остальные — нет. Отсюда и путаница «у меня открывается, у него нет».

Проверить можно снаружи, даже без доступа к панели:

bash
dig +short HTTPS ваш-домен @1.1.1.1

Если в ответе есть параметр ech=, режим включён. Выключается в Cloudflare: домен → SSL/TLS → Edge Certificates → Encrypted Client Hello → Off. После выключения тот же запрос не должен показывать ech=.

⚠️ На бесплатном тарифе переключателя может не быть вовсе. Мы столкнулись с этим на своём домене 15 сентября 2026: помогла только оплата платного тарифа, где настройка появляется.

Подключение домена к Cloudflare (для DNS-записей)

Cloudflare нужен как управляемый DNS (быстро создавать/менять записи) и опционально как CDN-фронт (вход через сеть-посредник вроде Cloudflare, чтобы прятать IP сервера).

Cloudflare → Add a site → введите ваш домен → план Free.
Cloudflare покажет два nameserver-а (вида xxx.ns.cloudflare.com). Зайдите к регистратору (или в @vpnhub_registration_bot → «Мои домены» → «Сменить NS») и замените NS на эти два. Активация занимает от минут до пары часов.
DNS → Records → Add record: создайте A-записи:
Имя	Содержимое	Proxy (облако)	Зачем
node1	IP ноды	DNS only (серое)	Reality и прямые ноды идут без проксирования CF
a7f3 (панель)	IP панели	DNS only	панель не светим, CF не нужен
sub	IP подписки	DNS only (или Proxied)	страница подписки
cdn	IP ноды-origin	Proxied (оранжевое)	только если фронтите XHTTP за CF
SSL/TLS → режим Full (или Full (strict)).

Важно: для нод с Reality ставьте серое облако (DNS only). Оранжевое (Proxied) терминирует TLS на Cloudflare и ломает Reality. Проксирование (оранжевое) подходит только для CDN-фронтинга XHTTP/WS (см. «Спрятать сервер за CDN»).

Cloudflare → Add record: тип A, имя = ваш сабдомен, content = IP (скрыт). Для нод с Reality переключатель Proxy status обязательно в положение «DNS only» (серое облако).
