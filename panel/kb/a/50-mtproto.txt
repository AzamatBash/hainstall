Заголовок: MTProto-прокси

MTProto-прокси это нативный для Telegram способ доступа: работает прямо внутри приложения, без отдельного клиента. Для VPN-бизнеса он ценен двумя вещами:

Резервный канал. Когда Telegram замедляют, MTProto часто остаётся доступным: полезно держать как запасной вход в мессенджер.
Бесплатный рост канала. Прокси можно сделать спонсорским: ваш канал будет закреплён сверху в списке чатов у каждого, кто пользуется прокси. Это работает как постоянная встроенная реклама.

📖 Незнакомые слова? Все термины простыми словами объяснены в Словаре терминов.

Честно про 2026: с весны 2026 РКН целенаправленно давит FakeTLS-прокси (научились отличать поддельный TLS от настоящего по микропаттернам рукопожатия). MTProto уже не серебряная пуля: держите его как резерв и инструмент роста, а основной обход стройте на VLESS/Reality (см. «Профили подключений»). Помогает: мимикрия под реальный сайт (mtg Doppelganger), ротация IP/доменов, нестандартные порты.

Сразу важно: «спонсорский канал» не подписывает людей насильно (Telegram это запрещает); он лишь показывает ваш канал закреплённым у пользователей прокси. Подписку они оформляют сами. Это честный приток, а не накрутка.

Сервер

MTProto нетребователен: хватит самого дешёвого VPS. Подойдёт любой минимальный тариф: 1 ядро, 512 МБ–1 ГБ памяти, безлимитный трафик. Выбирайте хостера из таблицы в статье Сервер за 15 минут — там же сказано, кого брать не стоит. Берите локацию, до которой стабильно доходит трафик из РФ.

bash
apt update && apt -y install docker.io ufw curl
ufw allow 22/tcp && ufw allow 443/tcp && ufw --force enable # MTProto — это TCP/443, UDP не нужен

Что спросит при установке:

Домен для FakeTLS-маскировки: ya.ru (рекомендуется), dzen.ru, www.google.com, www.microsoft.com или свой. Берите крупный живой сайт с TLS 1.3, не заблокированный в РФ.
Тип секрета: FakeTLS (маскировка под выбранный домен), обычный hex (без маскировки) или свой готовый.
Порт: 443 / 8443 / 80 / свой. Если порт занят, скрипт сам найдёт свободный.
Спонсорский TAG: можно пропустить, а можно сразу привязать канал (пошаговая инструкция по @MTProxybot прямо в скрипте).

В конце выведет ссылку https://t.me/proxy?server=… и сохранит всё в ~/mtproto_config.txt.

🧩 Что мы поправили в скрипте (v4.0 → v4.1). Оригинал собирал FakeTLS-секрет нестандартно: клал hex домена внутрь секретной части и всегда выдавал 32 символа, тогда как клиенты Telegram ждут ee + 32 hex + hex(домена). Побочные эффекты были ощутимые: на www.google.com на случайную часть оставалось 2 символа (секрет подбирался перебором), а www.microsoft.com вовсе ронял установку (head: illegal byte count, потому что длина домена уходила в минус). В нашей версии секрет собирается по стандарту, случайная часть всегда честные 16 байт, длина домена ни на что не влияет; мы разделили секрет сервера и секрет клиента (это заодно чинит смену TAG: раньше в контейнер уходил клиентский секрет). Плюс мы убрали зависимость от xxd, которого нет в базовой Ubuntu, вместо него используется od из coreutils.

Дальше то же самое руками, если хотите понимать каждый шаг.

Вариант A: со спонсорским каналом (официальный proxy)

Спонсорский тег (TAG) поддерживает официальный прокси Telegram. Это и есть путь «продвигать канал».

bash
# секрет: 16 байт = 32 hex-символа
SECRET=$(head -c 16 /dev/urandom | xxd -ps)
echo "SECRET=$SECRET"

# запуск (TAG добавим следующим шагом)
docker run -d --name mtproxy --restart unless-stopped \
 -p 443:443 -v mtproxy-data:/data \
 -e SECRET=$SECRET \
 telegrammessenger/proxy:latest

Сделать прокси спонсорским (через @MTProxybot)
Откройте @MTProxybot → команда /newproxy.
Введите IP:443 вашего сервера, затем секрет ($SECRET сверху).
Бот вернёт proxy tag (32 hex-символа).
В боте привяжите ваш канал к этому прокси (/setpromo → выбрать канал).
Перезапустите прокси с тегом:
bash
docker rm -f mtproxy
docker run -d --name mtproxy --restart unless-stopped \
 -p 443:443 -v mtproxy-data:/data \
 -e SECRET=$SECRET -e TAG=ВАШ_ТЕГ_ОТ_БОТА \
 telegrammessenger/proxy:latest

Готово: теперь у всех, кто подключится к прокси, ваш канал будет закреплён сверху.

Вариант B: максимальный стелс (mtg v2, FakeTLS)

mtg v2 даёт лучшую маскировку (чистый FakeTLS + мимикрия под реальный сайт), но спонсорский тег в v2 убрали: этот вариант для стелса, без продвижения канала. Можно держать оба: A (официальный, с каналом) как основной, B (mtg) как стелс-резерв.

bash
# секрет FakeTLS под домен-маскировку (SNI), напр. под dzen.ru
docker run --rm nineseconds/mtg:2 generate-secret dzen.ru
# -> ee.... (этот секрет отдаём клиенту)

config.toml:

toml
secret = "ee....ВАШ_СЕКРЕТ"
bind-to = "0.0.0.0:443"

# мимикрия под реальный сайт (устойчивее к DPI 2026)
[defense.doppelganger]
urls = ["https://dzen.ru/"]

Запуск:

bash
docker run -d --name mtg --restart unless-stopped \
 -v $PWD/config.toml:/config.toml -p 443:3128 \
 nineseconds/mtg:2
docker exec mtg /mtg access /config.toml # выдаст ссылку https://t.me/proxy?...

FakeTLS-домен (SNI): берите крупный «живой» сайт с TLS 1.3, не заблокированный в РФ (dzen.ru, www.yandex.ru, www.microsoft.com). Не берите домен, который сам зарезан.

Дать прокси клиентам

🔑 Из чего состоит секрет. Обычный секрет это ровно 32 hex-символа (16 байт), их и получает сервер. FakeTLS-секрет, который вы отдаёте клиенту, это ee + те же 32 hex + домен в hex: например для ya.ru получается 44 символа, а хвост 79612e7275 и есть закодированный ya.ru. Отсюда два практических вывода: клиентский секрет всегда длиннее серверного, а домен в нём не секрет: он виден любому, кто посмотрит ссылку. Если видите «FakeTLS-секрет» ровно в 32 символа: он собран неправильно.

Ссылка вида https://t.me/proxy?server=IP&port=443&secret=ee...: кидайте в канал/бот; по тапу Telegram сам предложит подключиться. Удобно положить кнопку «Бесплатный Telegram-прокси» в бота: это и точка входа в воронку (человек подключился → увидел ваш спонсорский канал → пришёл за VPN).

Чего MTProto не даёт
Это доступ только к Telegram. Остальной интернет через него не ходит: это не замена VPN.
Он больше не «серебряная пуля». Маскировку научились распознавать, и прокси живёт меньше, чем раньше.
Спонсорский канал не приводит подписчиков сам. Он лишь показывает канал наверху списка: подписываются люди сами и далеко не все.
Адрес сгорает. Публичный прокси, который вы раздали в канал, живёт ровно до тех пор, пока его не заметят.
Трафик видит владелец прокси. То есть вы: метаданные проходят через ваш сервер, и это ответственность, а не бонус.

Связано: «Профили подключений» и «Заблокировали IP?» (основной обход); «Бот для продаж» (продажи и воронка).
