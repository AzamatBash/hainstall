Заголовок: 3x-ui с нуля: установка панели и первый вход

За пять минут вы поставите панель на свой сервер и зайдёте в веб-интерфейс, закрыв вход паролем и отдельным путём. Подходит, если у вас один сервер: личный VPN, тестовый стенд, пара друзей. Планируете несколько серверов и продажу доступа — эта статья не про вас, читайте «Remnawave с нуля».

3x-ui — веб-панель для Xray (ядро, которое реально гоняет трафик), которая живёт на самом сервере вместе с этим ядром. Один сервер = одна панель = одна нода. Это её главное отличие от Remnawave, где панель управляет многими нодами по сети.

📖 Незнакомые слова? Все термины простыми словами есть в Словаре терминов.

Когда брать 3x-ui, а когда Remnawave
	3x-ui	Remnawave
Серверов	один (панель на ноде)	много нод из одной панели
Порог входа	ниже: поставил и работаешь	выше: панель, ноды, сквады, хосты
Клиенты	внутри панели	сквады + страница подписки
Кому	1 сервер, первый запуск, личный VPN, тест	сервис на продажу, рост, много стран

Если планируете продавать доступ и держать несколько стран — сразу смотрите «Remnawave с нуля». Если нужен один рабочий сервер сегодня — 3x-ui ставится за пять минут.

Что нужно
Чистый VPS (виртуальный сервер, арендованный у хостера): Ubuntu 22.04/24.04 или Debian 12, от 1 CPU / 1 ГБ RAM (этого хватает на сотню клиентов).
Root-доступ (максимальные права администратора) по SSH.
Домен не обязателен — для первого запуска хватит IP.

⚠️ Ставьте панель на чистый сервер. Если на машине уже крутится другая панель или свой Xray, они подерутся за порт 443 и за конфиг ядра.

Шаг 1: установка одной командой

Подключитесь к серверу по SSH и выполните официальный скрипт (репозиторий MHSanaei/3x-ui — это и есть «тот самый» 3x-ui):

bash
bash <(curl -Ls https://raw.githubusercontent.com/MHSanaei/3x-ui/master/install.sh)

Скрипт сам поставит Xray, панель и systemd-сервис (служба Linux, которая держит программу запущенной и поднимает её после сбоя) x-ui. В конце он спросит, задать ли логин, пароль и порт панели — отвечайте «y» и задайте свои. Если пропустить, панель останется на стандартных admin/admin, а это верный способ отдать сервер чужим людям.

Проверить, что панель поднялась:

bash
systemctl status x-ui --no-pager

Строка active (running) — панель работает.

Шаг 2: задайте доступы (если не сделали при установке)

У панели есть текстовое меню — вызывается командой x-ui. Через него меняются логин, порт и путь панели:

bash
x-ui

Нужные пункты меню:

Reset Username & Password — логин и пароль администратора;
Reset Web Base Path — секретный путь панели (например /mysecretpanel);
Reset Panel Port — порт панели (по умолчанию 2053).

Посмотреть текущие настройки разом:

bash
x-ui settings

⚠️ Смените webBasePath. Панель на голом / находят сканеры за сутки: они перебирают порты и стучатся в корень. Секретный путь — это второй пароль, который стоит ноль усилий.

Шаг 3: первый вход

Откройте в браузере http://IP-сервера:2053 (плюс ваш webBasePath, если задали). Появится форма входа:

Форма входа 3x-ui. Язык переключается здесь же — панель полностью переведена на русский.

После входа открывается дашборд — состояние сервера и ядра Xray:

Дашборд: слева состояние Xray · Running и версия ядра, дальше CPU/RAM/диск, скорость и открытые соединения. Кнопки Restart и Logs вверху — первое, куда идти при проблемах.

Что важно на дашборде:

Xray · Running и версия ядра — если тут Stopped, протоколы работать не будут, смотрите Logs.
CPU / RAM — на 1 ГБ сервере нормально видеть 30-40% RAM в покое.
Connection Stats — живые сокеты, по ним видно, что клиенты реально подключаются.
Шаг 4: закройте панель от посторонних

Пока панель висит на голом IP по HTTP, пароль ходит открытым текстом. Минимум, что нужно сделать:

Смените порт с дефолтного 2053 на произвольный (x-ui → Reset Panel Port).
Задайте webBasePath — секретный путь.
Включите HTTPS (шифрованное соединение до панели, без него пароль идёт по сети открытым текстом): в панели Panel Settings можно указать сертификат (файл, который подтверждает подлинность сайта и включает HTTPS). Если есть домен, получите бесплатный сертификат прямо из меню x-ui (пункт SSL Certificate Management, выпуск через Let's Encrypt).
Ограничьте доступ по IP файрволом, если заходите с одного адреса:
bash
ufw allow from ВАШ.IP.АДРЕС to any port 2053 proto tcp

Подробный разбор защиты панели и доступов — в статье «Защита панели и доступов»: она общая для любых панелей.

Если не получилось
Симптом	Что проверить	Что сделать
Забыли пароль, порт или путь панели	x-ui settings покажет текущие значения	Меняются там же, x-ui → пункты Reset. Переустановка не нужна
Открываю IP:порт в браузере — страница не грузится	Файрвол на сервере и у хостера	ufw status; откройте нужный порт в обоих местах (см. Шаг 4)
После правки настроек Xray показывает Stopped	Логи на дашборде, кнопка Logs	Часто порт уже занят: ss -tlnp sport =:443 покажет, кто там висит (обычно nginx)
Ставили панель на сервер, где раньше был Xray или другая панель	systemctl status x-ui — нет ли второго процесса	Снесите старую установку полностью, иначе они по очереди перехватывают порт
Скрипт установки падает с ошибкой	Версию ОС и архитектуру сервера	Нужна чистая Ubuntu 22.04/24.04 или Debian 12; иначе — по README MHSanaei/3x-ui
Чего это не даёт
Не управляет несколькими серверами. Второй сервер — вторая установка и своя база клиентов, а не рост одной системы.
Не защищает себя сама. Путь, порт, пароль и HTTPS панель не включает по умолчанию — это шаг 4 руками.
Не делает бэкапы автоматически. База копируется вручную, см. «Защита панели и бэкап».
Не даёт общей подписки на несколько стран. Для этого нужна Remnawave.
Что дальше

Панель поднята, но клиентов она пока не обслуживает — нужен inbound (входящее подключение с протоколом). Следующий шаг: «3x-ui: первый inbound VLESS-Reality» — создаём рабочий протокол по шагам в веб-интерфейсе.
