Заголовок: VLESS-TCP-TLS

Честный TLS (шифрование обычным сертификатом, как у любого HTTPS-сайта в браузере) на вашем домене. Настройка простая: выпустить сертификат и вставить один конфиг-профиль, займёт 10–15 минут. Берите этот вариант, если сервер стоит за CDN или просто нужен рабочий профиль без лишней возни. Для скрытности в России он слабее: имя вашего домена (SNI, Server Name Indication — то, что сервер и клиент открыто называют друг другу в начале TLS-соединения) видно любому наблюдателю и его можно заблокировать по списку доменов, тут Reality устойчивее. Берут ради CDN-совместимости, не как РФ-стелс. Сравнение смотрите в обзоре «Какой протокол выбрать».

📖 Незнакомые слова? Все термины простыми словами смотрите в Словаре терминов.

Шаг 1: выпустите сертификат
bash
apt -y install certbot
certbot certonly --standalone -d your.domain -m you@example.com --agree-tos --non-interactive

Должно получиться: certbot отчитается об успешном выпуске, а сертификат ляжет в /etc/letsencrypt/live/your.domain/ — файлы fullchain.pem и privkey.pem понадобятся в конфиге ниже. Флаг --standalone держит порт 80 занятым сам, поэтому на время выпуска на сервере не должно быть другого веб-сервера на этом порту.

Готовый Config Profile (вставляется целиком)
js
{
 "log": { "loglevel": "none" },
 "inbounds": [
 {
 "tag": "vless-tls",
 "listen": "0.0.0.0",
 "port": 443,
 "protocol": "vless",
 "settings": {
 "clients": [],
 "decryption": "none",
 "fallbacks": [{ "dest": "8080" }]
 },
 "sniffing": { "enabled": true, "destOverride": ["http", "tls", "quic"] },
 "streamSettings": {
 "network": "raw",
 "security": "tls",
 "tlsSettings": {
 "serverName": "your.domain",
 "minVersion": "1.2",

 {
 "certificateFile": "/etc/letsencrypt/live/your.domain/fullchain.pem",
 "keyFile": "/etc/letsencrypt/live/your.domain/privkey.pem"
 }
 ]
 }
 }
 }
 ],
 "outbounds": [
 { "tag": "DIRECT", "protocol": "freedom" },
 { "tag": "BLOCK", "protocol": "blackhole" }
 ],
 "routing": { "rules": [
 { "ip": ["geoip:private"], "outboundTag": "BLOCK" },

fallback (запасной адрес) → dest 8080: «левый» трафик — кто угодно, кто зашёл на ваш домен без верного ключа клиента, — уйдёт на реальный сайт/nginx на:8080, чтобы при «тыке» браузером отдавалась обычная страница, а не ошибка. Серт нужно автообновлять (certbot renew по крону) и перезапускать ноду.

Host в Remnawave
text
Address: your.domain
Port: 443
SNI / Host: your.domain
ALPN: h2, http/1.1
flow: (пусто)
fingerprint: firefox

ALPN (Application-Layer Protocol Negotiation) — список протоколов поверх TLS, которые клиент предлагает серверу; h2 — это HTTP/2. fingerprint — отпечаток, «почерк» TLS-клиента, его подделывают под браузер, чтобы TLS-рукопожатие не выделялось на общем фоне.

Грабли
SNI вашего домена виден, поэтому под жёстким РФ-DPI его могут резать по списку. Если режут, переходите на Reality/Selfsteal.
Серт живёт 90 дней, поставьте certbot renew в cron + рестарт ноды (иначе отдаётся старый серт).
Хорошо ложится за CDN, но для CDN чаще берут XHTTP (см. «Спрятать сервер за CDN»).
В России блокируют по адресу сервера целиком, а не по портам и протоколам: если IP уже в блок-листе, перестают отвечать все порты сразу и честный TLS тут не спасает — только смена адреса или CDN.
Актуальный стабильный Xray-core на сентябрь 2026 — 26.3.27, более новые сборки (вплоть до 26.9.9) — предварительные, для боевой ноды разумнее ставить стабильную ветку.
Если не получилось
Симптом	Что проверить	Что сделать
certbot падает с ошибкой занятого порта	Не висит ли на 80/443 другой веб-сервер: ss -tlnp sport =:80	Остановите его на время выпуска сертификата либо запускайте certbot с плагином под ваш веб-сервер вместо --standalone
Браузер или клиент ругается на сертификат	Срок действия: certbot certificates	Сертификат просрочен — обновите certbot renew, затем перезапустите ноду, иначе она продолжит отдавать старый файл
Клиент не может подключиться вовсе	Совпадает ли serverName в конфиге с реальным доменом и не занят ли порт 443 другим сервисом	Исправьте serverName или освободите порт под ноду
По домену в браузере открывается ошибка вместо сайта-прикрытия	Поднят ли веб-сервер на порту из fallbacks → dest (в примере 8080)	Запустите на этом порту реальный сайт/nginx либо поменяйте номер порта на тот, где он уже слушает
Из России клиент не достаёт до домена совсем	Открывается ли домен в обычном браузере без VPN из РФ	Если не открывается — домен или адрес сервера уже заблокированы, нужен новый домен либо переход на Reality/Selfsteal
Сертификат исправно работал, а потом резко перестал	Не истекли ли все 90 дней с выпуска и есть ли задача автообновления	Добавьте certbot renew в cron и рестарт ноды после обновления
Чего VLESS-TCP-TLS не умеет
Не прячет домен. SNI передаётся открытым текстом, при желании его блокируют по списку — тогда нужен Reality/Selfsteal.
Не маскирует профиль трафика, как Vision в Reality: при глубоком анализе пакетов туннель заметнее.
Требует ухода за сертификатом: обновление каждые 90 дней и перезапуск ноды, иначе клиенты получают просроченный серт.
Fallback — это заглушка, а не полноценный сайт-прикрытие: за ним должен реально стоять веб-сервер, иначе «левые» посетители увидят ошибку.
Не спасает от блокировки по IP-адресу сервера — если адрес уже заблокирован, TLS и честный домен ничего не меняют.

Полный список профилей смотрите в статье «Профили подключений (inbounds)», а обзор протоколов дан в статье «Какой протокол выбрать».

Проверено на Xray-core 26.3.27 и Remnawave 3.4.x — сентябрь 2026.
