Заголовок: Self-steal с nginx: Reality под вашим сайтом

Что это. Обычный Reality «крадёт» рукопожатие у чужого сайта — его называют донором (в конфиге это target: google.com или похожий адрес): соединение выглядит так, будто вы зашли на этот чужой сайт. Слабое место в том, что SNI донора (SNI, Server Name Indication — имя сайта, которое видно в открытую в самом начале TLS-соединения, ещё до включения шифрования) не резолвится в ваш IP: при глубокой проверке это заметный рассинхрон — имя одно, а адрес принадлежит другому.

Self-steal эту нестыковку убирает: вместо чужого сайта Reality «крадёт» ваш собственный. serverNames (тот же самый SNI) — это ваш домен с A-записью на ноду, а target — ваш же сайт-обманка на локальном nginx. Имя, адрес и содержимое совпадают, и при активном прозванивании DPI попадает на настоящий работающий сайт.

Что получится. Сайт-заглушка на nginx (свой мини-сайт, который отвечает на unix-сокете — это специальный файл на диске, через который две программы на одной машине обмениваются данными быстрее, чем через сеть) плюс инбаунд Reality по официальному шаблону Remnawave, с PROXY-protocol, чтобы в логах сайта было видно настоящий IP клиента, а не одну и ту же заглушку 127.0.0.1.

Сколько времени. Домен и DNS уже настроены — 20–30 минут: пакеты, сертификат, конфиг. Домена ещё нет — добавьте время на покупку и на распространение A-записи (обычно от нескольких минут до пары часов).

Кому нужно. Тем, у кого уже есть свой домен или кто готов завести его ради максимальной устойчивости к DPI. Домена нет и заводить не хотите — возьмите обычный VLESS-Reality с чужим донором (см. «Какой протокол выбрать»): настройка проще, но под глубокой проверкой чуть менее стойкая.

В официальном шаблоне Remnawave это делается через unix-сокет (/dev/shm/nginx.sock) и PROXY-protocol (xver: 1 — способ передать nginx настоящий IP клиента поверх этого же сокета).

Быстрый путь: скрипт-установщик сайта-обманки

Если не хотите собирать декой руками, есть готовый установщик от DigneZzZ (github.com/DigneZzZ/remnawave-scripts). Он сам поднимает self-steal сайт на Caddy (с набором из ~8 готовых шаблонов-страниц, сертификатом и маскировкой под Reality):

bash
bash <(curl -Ls https://github.com/DigneZzZ/remnawave-scripts/raw/main/selfsteal.sh) @ install

Должно получиться: скрипт спросит домен, даст выбрать шаблон страницы и сам поднимет сайт с сертификатом. Для сайта-обманки это удобно: объект одноразовый, секретов не хранит; если отработал криво, просто перезапустили. После установки в Config Profile укажите target/dest на адрес-порт, который покажет скрипт, а serverNames = ваш домен (логика та же, что в ручном варианте ниже, только вместо nginx используется Caddy).

⚠️ Этим же репозиторием НЕ ставьте панель и ноды. Там есть remnawave.sh (панель) и remnanode.sh (нода), но их лучше ставить вручную (официальный docker-compose, см. «Remnawave с нуля»). Почему:

Панель это всё ваше хозяйство (БД пользователей, JWT-секреты, привязки оплат). По отзывам сообщества, сторонний скрипт иногда отрабатывает криво; для одноразового декоя это пустяк (перезапустил), а для панели полусломанная установка = тяжёлая диагностика и риск повредить/потерять данные клиентов.
Надо знать, что и куда поставлено: где .env и секреты, какие порты, как бэкапить и обновлять. Ручная установка по офиц. докам даёт полный контроль; скрипт-обёртка это прячет и усложняет восстановление.
Версии и дефолты: сторонний скрипт может отставать от релизов Remnawave или менять дефолтные настройки/порты, и потом сложно сверяться с официальной документацией.
Supply-chain: запускать чужой скрипт рутом на хосте, где лежат ключи всех клиентов, это лишняя поверхность риска; для «коронной драгоценности» её минимизируют.

Итог: скриптом ставьте только сайт-обманку; панель и ноды разворачивайте руками.

Ниже разберём ручной вариант на nginx (если хотите всё контролировать или уже стоит nginx).

Шаг 1: сайт-обманка на nginx (unix-сокет)
bash
apt update && apt -y install nginx
mkdir -p /var/www/decoy
echo '<!doctype html><title>Welcome</title><h1>It works</h1>' > /var/www/decoy/index.html

Должно получиться: nginx установлен, а по пути /var/www/decoy/index.html лежит заготовка страницы — свериться можно командой cat /var/www/decoy/index.html.

В конфиге /etc/nginx/sites-available/decoy nginx слушает unix-сокет с proxy_protocol:

nginx
server {
 listen unix:/dev/shm/nginx.sock ssl proxy_protocol;
 server_name your.domain; # ← ваш домен
 ssl_certificate /etc/letsencrypt/live/your.domain/fullchain.pem;
 ssl_certificate_key /etc/letsencrypt/live/your.domain/privkey.pem;
 ssl_protocols TLSv1.3;
 set_real_ip_from unix:; # реальный IP клиента из PROXY-protocol
 real_ip_header proxy_protocol;
 root /var/www/decoy;
 location / { try_files $uri /index.html; }
}

Должно получиться: файл /etc/nginx/sites-available/decoy с этим содержимым — домен впишите свой везде, где написано your.domain.

Сертификат для домена (Reality отдаёт клиенту именно его):

bash
apt -y install certbot && certbot certonly --standalone -d your.domain
ln -s /etc/nginx/sites-available/decoy /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx

Должно получиться: certbot напишет, что сертификат сохранён в /etc/letsencrypt/live/your.domain/ (путь совпадает с тем, что в конфиге выше). nginx -t ответит syntax is ok и test is successful, после чего сайт перезапустится с новым конфигом.

Сокет в /dev/shm (tmpfs): быстро и доступно и nginx, и ноде. Если нода в Docker, пробросьте сокет в контейнер (-v /dev/shm:/dev/shm) или используйте порт 127.0.0.1:8443 вместо сокета.

Шаг 2: инбаунд в Config Profile (официальный шаблон)

Инбаунд (inbound, «входная точка» на ноде: связка протокол + порт + настройки, куда стучится клиент) для self-steal собирается так:

js
{
 "log": { "loglevel": "none" },
 "inbounds": [{
 "tag": "VLESS_SELFSTEAL",
 "port": 443, "protocol": "vless",
 "settings": { "clients": [], "decryption": "none" },
 "sniffing": { "enabled": true, "destOverride": ["http","tls","quic"] },
 "streamSettings": {
 "network": "raw",
 "security": "reality",
 "realitySettings": {
 "xver": 1, // PROXY-protocol -> реальный IP в nginx
 "target": "/dev/shm/nginx.sock", // ваш сайт-обманка
 "spiderX": "",
 "shortIds": [""],
 "privateKey": "PRIVATE_KEY", // ← из генератора панели
 "serverNames": ["your.domain"] // ← ваш домен
 }
 }
 }],
 "outbounds": [
 { "tag": "DIRECT", "protocol": "freedom" },
 { "tag": "BLOCK", "protocol": "blackhole" }
 ],
 "routing": { "rules": [
 { "ip": ["geoip:private"], "outboundTag": "BLOCK" },
 { "protocol": ["bittorrent"], "outboundTag": "BLOCK" }
 ]}
}

Поменять: privateKey (генератор x25519 в панели), serverNames (ваш домен). clients: [] не трогать.

Должно получиться: панель Remnawave примет конфиг без ошибок (внизу редактора — «Xray config is valid»).

Шаг 3: Host в Remnawave (Advanced)

В Hosts → создать host: - Inbound = VLESS_SELFSTEAL - Address = ваш домен (A-запись на ноду), Port 443 - Security = reality - SNI = your.domain - Public Key = publicKey из той же пары - Short ID = как в конфиге (или пусто) - Fingerprint = firefox или qq

Должно получиться: новый Host в списке, готовый выдавать конфиги клиентам. Полную привязку профиль→нода→host→сквад смотрите в статье «Все рабочие конфиги».

Проверка стелса

Откройте https://your.domain в браузере: должен открыться сайт-обманка (не ошибка). Значит и DPI при активном прозвоне увидит обычный сайт на вашем домене.

Сделайте сайт-обманку правдоподобным (не пустую страницу): лендинг, блог, что угодно «живое». Связано: «Все рабочие конфиги», «Заблокировали IP?».

Реальный IP клиента в логах сайта

Когда перед Xray стоит фронт (Nginx или Caddy) или работает fallback (запасной обработчик: если протокол клиента не подошёл под инбаунд, соединение передаётся дальше — например, на настоящий сайт), сайт-заглушка видит соединения с 127.0.0.1: все посетители «изнутри». Для маскировки это плохо: логи настоящего сайта так не выглядят.

Лечится PROXY protocol: фронт передаёт адрес клиента дальше, Xray его принимает и пробрасывает на сайт.

inbound

json
"streamSettings": {
 "rawSettings": { "acceptProxyProtocol": true }
}

А в самом REALITY: "xver": 1, чтобы адрес доехал до сайта-донора. В Nginx на стороне фронта включается proxy_protocol on.

Подробнее про схемы с фронтом и fallback смотрите в статье Эталонные схемы размещения.

Чего self-steal не даёт
Требует денег и времени. Домен, сертификат, настоящий сайт на ноде — это не «включить галочку», а отдельная небольшая работа.
Не защищает от блокировки по адресу. Если IP ноды уже в бане, self-steal не поможет: это лечится только сменой адреса или CDN.
Сайт-заглушку нужно делать правдоподобной самому. Страница «It works» из шага 1 годится для проверки, что всё собралось, но не выдержит внимательного взгляда — под неё нужен настоящий лендинг или блог.
Unix-сокет привязывает nginx и ноду к одной машине. Нода в Docker — нужен либо проброс сокета в контейнер, либо TCP-порт вместо сокета: это дополнительная настройка.
Один сайт — одна точка отказа для маскировки. Если nginx упал, стелс пропадает (сам VPN-трафик при этом может продолжать идти) — это заметит тот, кто станет специально прозванивать домен.
PROXY-protocol нужно включать сразу с двух сторон. Забыли одну из них (в Xray или в nginx) — реальный IP в логах не появится, и это легко не заметить.

Проверено на Xray-core 26.x и Remnawave 3.4.x — сентябрь 2026.
